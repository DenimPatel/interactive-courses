{%- comment -%} The no-flash boot. Include this as the FIRST thing in , before any stylesheet link, on every page that renders one. It duplicates two things from assets/js/preferences.js on purpose: how a stored preference set is read, and how a preference maps to a CSS value. The module cannot do this job because it is a deferred external file — by the time it runs the browser has already decided what colour the first frame is. A reader who chose Dark has to never see a light frame, and that guarantee can only be made from an inline script that runs before first paint. THE CONSTRAINT: this is inlined into ~570 pages and served by GitHub Pages to everything, so it is ES3/ES5-safe. No `const`, no `let`, no arrow functions, no template literals, no optional chaining, no `Array.prototype.includes`, no `Object.assign`. `var`, functions, string concatenation, and try/catch, and the whole body is wrapped so that a thrown error cannot leave the page half-themed. It is written as a function on `window` rather than a bare IIFE so that _includes/site-nav.html can call it again. Roughly thirty standalone guide pages carry a hand-written and never include this file; on those the first shot at the theme happens after has begun, so site-nav re-runs the boot. Re-running is safe — every write below is idempotent — and it is skipped entirely on a page whose head already booted, which is all 540 of the others. THEME-COLOUR NOTE. `--c-bg-ch` is `242 245 250` in light and `9 12 17` in dark, i.e. #f2f5fa and #090c11. The sibling site hard-codes #f7f8fa against its own identical #f2f5fa canvas; that is a five-point drift, and the bug is not copied here. {%- endcomment -%}
